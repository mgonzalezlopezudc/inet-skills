# Skill-suite baseline — 2026-09-03

This is the pre-routing-change baseline for the 23 skills that existed before the improvement
program. It uses the unchanged activation, workflow, and routing corpus under
`tests/skill-suite/`. The measurements are a static frontmatter and workflow audit; no model runner
was available to observe live skill loads, turns, tokens, or wall-clock runtime.

## Results

| Metric | Baseline | Method |
| --- | ---: | --- |
| Activation accuracy | 45 / 46 (97.8%) | Manual audit of each prompt against pre-change frontmatter |
| Workflow correctness | 7 / 7 | Manual audit of required semantic gates against pre-change skill instructions |
| Routing acceptance | 4 / 6 | Manual audit against the pre-change orchestration and authoring paths |
| Unnecessary skill loads | 1 | `inet-agent-orchestration` on the localized single-agent production change |
| Turns | NOT_RUN | Requires a platform evaluation runner |
| Tokens | NOT_RUN | Requires platform token accounting |
| Runtime | NOT_RUN | Requires platform timing around the same corpus |

The activation failure and one routing failure have the same cause: orchestration frontmatter names
ordinary nontrivial C++/NED/MSG work even when there is no delegation or independent evidence lane.
The other routing failure is the absent behavior-preserving mechanical path: a wide rename falls
through to the semantic pipeline despite having an independently checkable no-behavior-change
invariant.

## Static inventory

- Skills: 23.
- Activation cases: 46, with at least one positive and one negative case per skill.
- Representative workflow cases: 7 (authoring, review, debugging, results, regression, branch
  cleanup, and branch rebase).
- Local Markdown links: 42; all resolve.
- Orphan references: one, `inet-code-review/references/high-value-flag-checks.md`, recorded as a
  temporary manifest exception.
- Platform metadata: all 23 OpenAI/Antigravity pairs are byte-for-byte identical.
- Ignored bytecode observed inside the source/deployment copy: four `*.pyc` files under two
  `__pycache__` directories.

## Unsupported or unavailable capabilities

- No protocol-neutral regression-design skill.
- No common machine-readable verification envelope or runner adapters.
- The walkthrough profile is unavailable because both shared analyzer capability files are absent
  in the active INET checkout.
- `opp_scavetool` is not on the current shell's `PATH`; the result skills remain installable but
  their command capability cannot be exercised in this environment.
- Live model-evaluation instrumentation for turns, tokens, runtime, and observed skill loads is not
  part of this repository. These metrics remain `NOT_RUN` rather than being inferred from prose.

This report is the comparison point. Post-change evaluation must retain the same case IDs and
semantic gates; additional cases may cover newly added skills.
