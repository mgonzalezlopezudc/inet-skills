# Use current INET project guidance

Use this skill to work from current contributor documents without a separate copy of their policy.
Start with [project-guidance-discovery.md](../../references/project-guidance-discovery.md).
Identify the active INET checkout before you select a document route.

## Prepare or review a plan

Read the current map's route for implementation plans.
Read the procedure, its policy, and the technical documents relevant to the proposed behavior.
Check their status and conditions for use before you apply an approval process.

Inspect the actual caller, responsible component, consumers, and effective configuration before you describe the design.
Use the discovered plan structure, review criteria, storage location, and approval procedure.
Keep verified facts, proposed decisions, and unresolved assumptions distinct.
Keep proposed verification separate from executed evidence.
State the specific gap when the checkout lacks a required route or a proposed test does not yet exist.

Use the applicable architecture, standards, configuration, and regression skills when the plan needs their technical methods.
A request for a plan does not authorize implementation.
Record existing approval by its actual source and scope.

## Edit contributor documents

Read the current map's route for documentation.
Use it to identify the document that owns the fact and the audience that needs it.
Read the applicable status, protection, format, reference, and validation requirements before an edit.
For release notes or compatibility guidance, also follow the current release route.

Edit the owning document within the requested scope.
Use links where the current documentation policy requires a reference to another owner.
Use the current vocabulary and the document's established structure.
Explain the responsible component, trigger, state change, result, failure behavior, and limits where they affect the reader.
Check that the document makes sense without the conversation.

## Return the result

Use the report format required by the selected project procedure.
Name the checkout, relevant local edits, guidance sources, completed work, and unverified items.
Identify any decision or permission that remains necessary.
Do not infer approval from a document link, a successful checker, or an agent review.
