# IEEE 802.11 bug-pattern examples

These hypothetical examples illustrate the named `RP-*` prompts. They are not findings by
themselves; establish the actual contract, reachable trigger, failure mechanism, and consequence in
the reviewed change. Verify normative details against the applicable IEEE 802.11 revision rather
than treating an example as a standards requirement.

## 11. Retry exhaustion never terminates a pending transaction

**Related prompts:** `RP-WLAN-TERMINAL-PATHS`, `RP-WLAN-TRANSACTION-TIMERS`, `RP-OMNET-TERMINAL-EVENTS`

An ADDBA manager creates a pending agreement and removes it after refusal, timeout, or DELBA, but the
request's transmit retry-limit path only drops the frame. That peer/TID remains pending and cannot
start a replacement negotiation.

## 12. Reassembly uses an incomplete identity and arrival order

**Related prompts:** `RP-WLAN-FRAGMENT-REASSEMBLY`, `RP-WLAN-SEQUENCE-WRAPAROUND`, `RP-WLAN-STATE-CONTEXT`, `RP-WLAN-WINDOW-BOUNDARIES`

A reassembly table is keyed only by sequence number and appends fragments in arrival order. Fragment
2 with More Fragments clear arrives before 0 and 1 while another transmitter uses the same sequence
number, allowing premature completion or fragments from different contexts to be joined.

## 13. A stale response matches a replacement transaction

**Related prompts:** `RP-WLAN-TRANSACTION-IDENTITY`, `RP-INET-TRANSACTION-GENERATIONS`, `RP-INET-OPERATION-IDENTITY`

A station times out ADDBA dialog token 7 and starts token 8 for the same peer and TID. A delayed
token-7 response arrives, and a lookup using only peer/TID applies it to the newer transaction.

## 15. Symmetric serializers repeat the same wire-layout error

**Related prompts:** `RP-INET-WIRE-LAYOUT`, `RP-INET-UNIT-CONVERSION`, `RP-WLAN-MANAGEMENT-PARSING`

An ADDBA serializer declares a nine-byte body but writes ten bytes because one field has the wrong
width. Its paired reader consumes the same incorrect layout, so local round trips pass while an
independent implementation rejects the frame. Field order, width, byte order, and units come from
the applicable wire contract, not from writer/reader symmetry.
